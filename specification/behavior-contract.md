# Behavior Contract

Clean-room specification for the Python and .NET implementations in this repository.

This repository uses only synthetic data and fictional operational events. It does not include employer code, private endpoints, customer data, production logs, device identifiers, proprietary firmware or proprietary business rules.

## Event Schema

Each workload line is a JSON object:

```json
{
  "asset_id": "ASSET-0001",
  "source": "edge-agent",
  "category": "offline",
  "severity": 91,
  "occurred_at": "2026-01-01T00:00:00Z",
  "message": "Synthetic offline event",
  "executor_mode": "success"
}
```

`executor_mode` supports `success`, `transient_failure` and `permanent_failure`.

## Rules

- `severity < 50`: persist event, write audit, no incident, no action. Canonical skipped reason: `normal`.
- `50 <= severity < 80`: persist event, open incident, write audit, no action. Canonical skipped reason: `warning_no_action`.
- `severity >= 80`: persist event, open incident, queue action, write audit. Canonical skipped reason: `null`.
- Cooldown is evaluated by `asset_id + category` against open incidents created during the previous 20 minutes. A duplicate event is persisted, but duplicate incident/action creation is suppressed and audited. Canonical skipped reason: `cooldown`.
- `success`: queued action succeeds on first attempt.
- `transient_failure`: same action ID fails once and succeeds on the second attempt.
- `permanent_failure`: same action ID is attempted three times, remains failed and records final failure audit.

## Canonical Summary

Both stacks must produce equivalent values for:

- `events`
- `incidents`
- `actions`
- `audit_logs`
- `normal_events`
- `warning_incidents`
- `suppressions`
- `action_succeeded`
- `action_failed`
- `retries`
- `errors`

Timing, CPU and memory metrics are benchmark evidence, not correctness criteria.

## Workloads

Workloads are generated by `benchmarks/generate_workloads.py` using fixed seeds and stored under `specification/workloads/`.

Generated sizes:

- `workload_100.jsonl`
- `workload_1000.jsonl`
- `workload_10000.jsonl`
- `workload_50000.jsonl`
